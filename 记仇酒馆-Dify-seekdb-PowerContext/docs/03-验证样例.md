## 样例 1｜第一次恶作剧：世界有边界，账本开始记

**初始状态**：`grudge=0, mood=60, turn_no=0`。

**输入**（Dify 对话框直接发送）：

> 我把吧台上的盐罐换成了糖罐

**预期交互**：

1. 老陈先接住这个动作（台词里会提到盐/糖/咖啡），不会直接说「好，我生气了」。
2. 回复底部出现状态面板，记仇值上涨到 **15–25**，账本一栏写着类似「把盐罐换成了糖罐」。
3. 道具栏显示「盐罐」「糖罐」之一（来自 seekdb 检索，而不是模型编造）。

**预期输出形状（示例）**：

```text
老陈把杯子端起来，闻了一下，又放下。
「今天的糖，怎么是咸的。」
他没看你，只是伸手把那只缺了口的盐罐挪远了半寸。

———
🍺 老陈的记仇本  ▮▮▯▯▯▯▯▯▯▯  18/100
🙂 心情 52/100 ｜ 第 1 回合 ｜ 记在账上：把盐罐换成了糖罐
🔧 本轮道具：盐罐
```

**怎么核对技术真的参与了**

```bash
# seekdb：本轮检索到了哪些道具（mode=hybrid 表示向量+全文都生效）
curl -X POST http://127.0.0.1:8099/v1/props/search \
  -H "Content-Type: application/json" \
  -d "{\"user_id\":\"demo-player\",\"query\":\"我把盐罐换成了糖罐\",\"limit\":6}"
```

```sql
-- seekdb：这一笔是否落库
SELECT turn_no, action, ledger, prop_used, grudge_after, mood_after
FROM turn_log WHERE user_id = 'demo-player' ORDER BY turn_no;
SELECT grudge, mood, turn_no FROM player_state WHERE user_id = 'demo-player';
```

```bash
# PowerContext：记忆是否写入（players.scope_id 就是该玩家的 scope）
curl -X POST http://127.0.0.1:8000/v1/context/prepare \
  -H "Content-Type: application/json" \
  -d "{\"scope_id\":\"<players.scope_id>\",\"query\":\"盐罐 糖罐\",\"max_bytes\":2000}"
```

期望返回的 `content` 里包含「第1回合」「盐罐换成了糖罐」。

## 样例 2｜跨会话记忆：换个会话，他仍然记得

> 这是本作品最核心的一条验证，直接对应评分里的「记忆如何被保存并在后续互动中复用」。

**初始状态**：完成样例 1 后，`turn_no=1, grudge≈18`。

**操作**：

1. **不要重置**。
2. 在 Dify 里**新建一个会话**（同一个账号）。
3. 发送：

   > 老陈，今天有什么喝的？

**预期交互**：

- 老陈的回复会主动提到上一回合的盐/糖事件（「你上次把盐换成了糖」「今天的咖啡不会又是咸的吧」之类），而不是重新自我介绍。
- 状态面板里的第 2 回合、记仇值延续 18（不是从 0 开始）。

**预期输出形状（示例）**：

```text
「有。」他头也不抬，「不过今天这杯，我先替你尝一口。」
他抿了一下，皱眉：「上次那罐盐，你换得挺顺手。」

———
🍺 老陈的记仇本  ▮▮▯▯▯▯▯▯▯▯  20/100
🙂 心情 48/100 ｜ 第 2 回合 ｜ 记在账上：还敢来点单
```

**证据点**：

- Dify 侧：两个会话的截图并排（会话 A 的恶作剧、会话 B 的第一句话）。
- PowerContext 侧：`/v1/context/prepare` 的返回内容含上一回合的记忆；`/v1/memory/remember` 的写入返回。
- seekdb 侧：`turn_log` 中 `turn_no=1` 与 `turn_no=2` 属于同一个 `user_id`，`grudge_after` 连续。

> 若新会话里老陈完全失忆：先查 `players.scope_id` 是否为空、PowerContext 是否健康；再确认 Dify 的 `sys.user_id` 在两个会话里是否一致（网页端同一账号应一致；若你的部署开了匿名访问，见运行说明 12 的已知限制）。

## 样例 3｜记仇爆表：结局分支

**初始状态**：`grudge≈20, turn_no=2`。

**操作**：连续发送 4–5 次恶作剧，例如：

1. 我把他的老花镜藏进冰桶里
2. 我把点唱机音量拧到最大
3. 我往他的抹布里挤了半管芥末
4. 我把「账本」抱到门口，让它在雨里待了一会儿
5. （如果还没到 100）我把他的记账本翻到最后一页，大声念出来

**预期交互**：

- 记仇值过 60 后，面板出现「⚠️ 老陈开始翻账本了」，台词开始执行报复剧本（换儿童杯、把拖把当伞、公开念账本……）。
- 某一次回复后，记仇值到 100，输出变成结局文案：纸箱、日期、「今晚这杯，我请你」。

**预期输出形状（示例）**：

```text
（老陈把抹布搭在肩上，走到门口，把「营业中」的牌子翻了过去。）

「第 7 回合。把记账本念出来……我都记着。」

他从吧台下面拖出一个纸箱：盐罐、气球、弹珠、那副假牙，每一件上面都贴着日期。
「今晚这杯，我请你。」

———
🏁 结局【打烊后的清算】
记仇 100/100 ｜ 共 7 回合 ｜ 心情 12/100
（灯灭了。明天，酒馆照常营业。）
```

**证据点**：

- Dify 运行详情里，`if_ending` 节点走的是 `true` 分支。
- `player_state.ending = 1`；`turn_log` 最后一条 `ending = 1`。
- PowerContext 里同时写入了结局记忆（kind=`state`）。

## 样例 4（可选）｜道歉的衰减：记忆影响规则，而不是计数器

**操作**（在样例 3 之前另起一局）：

1. 先做一次恶作剧（grudge ≈ 18）。
2. 发送：`我道歉，我不该换你的盐。`
3. 再发送：`我真的道歉，我保证不再犯了。`

**预期交互**：

- 第一次道歉，记仇值明显下降（约 -10~-25）。
- 第二次道歉，老陈会点破「你上次也这么说」，下降幅度变小（约减半），甚至不降。
- 这证明「道歉是否可信」来自 PowerContext 的历史，而不是写死的规则。

**证据点**：两条 `turn_log` 的 `grudge_after` 差值对比；PowerContext 中两次道歉记忆。

## 恢复初始状态

```bash
curl -X POST http://127.0.0.1:8099/v1/reset \
  -H "Content-Type: application/json" -d "{\"user_id\":\"demo-player\"}"
```

reset 会：清空 `turn_log`、把 `player_state` 归零、把 `players.scope_generation` +1 并在 PowerContext 新建一个 scope。旧记忆留在旧 scope，便于审计，也不会污染新一局。

## 一键冒烟（不经过 Dify）

```bash
python scripts/verify.py --base http://127.0.0.1:8099 --user demo-player
```

它会自动完成「reset → 检索 → 记忆写入 → 记忆召回 → 记仇爆表 → 再 reset」，并打印 `[PASS]/[FAIL]`。这个脚本用于快速确认三个后端组件是通的；**Dify 侧的体验仍需按样例 1–3 在界面里走一遍**。
