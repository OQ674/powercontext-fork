# 02 · 运行说明

> 本文按「一台机器、四个进程」写：**seekdb**（容器）、**PowerContext**（本机 uv）、**bridge**（本机或容器）、**Dify**（官方 Docker Compose）。评审只需按顺序执行，不需要作者本地任何未交付的状态。

## 0. 拓扑与端口

```text
浏览器 ──> Dify Web (80/3000)
                │  Chatflow 里两个 HTTP Request 节点
                ▼
        bridge :8099  ──> seekdb :2881
                └─────> PowerContext :8000
```

| 服务 | 默认地址 | 谁访问它 |
| --- | --- | --- |
| Dify Web/API | `http://localhost`（官方 compose 默认 80） | 浏览器 |
| bridge | `http://<宿主机>:8099` | Dify 容器（`host.docker.internal:8099`） |
| seekdb | `127.0.0.1:2881`（MySQL 协议） | bridge、初始化脚本 |
| PowerContext | `http://127.0.0.1:8000` | bridge |

## 1. 版本矩阵

| 组件 | 版本 | 获取方式 |
| --- | --- | --- |
| Dify | **1.16+**（DSL `version: "0.7.0"`） | `git clone https://github.com/langgenius/dify.git`，`docker/docker-compose.yaml` |
| seekdb | `oceanbase/seekdb` 最新镜像（V1.x） | `docker pull oceanbase/seekdb` |
| PowerContext | **1.5.0** | `uv tool install --force "powercontext[cli,server]==1.5.0"` |
| Python | 3.11+（bridge 与脚本） | — |
| 对话模型 | `deepseek-chat`（可替换） | Dify 模型供应商里安装 DeepSeek 插件并填 Key |
| Embedding | OpenAI 兼容、**1024 维**（默认百炼 `text-embedding-v3`） | 百炼 / OpenAI / 其他兼容服务 |

> 为什么 Embedding 只需要 bridge 配：道具检索发生在 bridge 里，Dify 的知识库没有参与本作品，Dify 端不需要 Embedding 模型。这也让「seekdb 承担应用数据存储与检索」的边界更清楚。

## 2. 前置条件

- Docker Desktop（或 Linux Docker + Compose v2），至少 8 GB 内存可分配。
- Python 3.11+，`pip`。
- 一个 Chat 模型 API Key（DeepSeek 或任意 OpenAI 兼容模型）。
- 一个 Embedding API Key（百炼/OpenAI）；**没有也能跑**，检索会降级为「全文 + 结构化」，见 9.2。
- 磁盘 ≥ 10 GB（Dify 镜像 + seekdb 数据）。

## 3. 启动 seekdb

```bash
docker run -d --name tavern-seekdb -p 2881:2881 \
  -e ROOT_PASSWORD=tavern-demo \
  -e MEMORY_LIMIT=2G \
  -v "$PWD/seekdb-data:/var/lib/oceanbase" \
  oceanbase/seekdb
```

首次启动需要 20–60 秒初始化。连接测试：

```bash
mysql -h127.0.0.1 -P2881 -uroot -ptavern-demo -e "SELECT 1"
# 或：docker exec -it tavern-seekdb bash -lc "mysql -uroot -ptavern-demo -e 'SELECT 1'"
```

## 4. 建表与灌数据

```bash
# 4.1 建库建表（二选一）
mysql -h127.0.0.1 -P2881 -uroot -ptavern-demo < seed/00_schema.sql
# Windows 没有 mysql 客户端时：
python scripts/init_schema.py

# 4.2 安装 bridge 依赖（seed 脚本也要用）
pip install -r bridge/requirements.txt

# 4.3 生成 1024 维向量并写入 seekdb
#     PowerShell:
$env:EMBED_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
$env:EMBED_API_KEY="sk-你的key"
$env:EMBED_MODEL="text-embedding-v3"
$env:EMBED_DIM="1024"
python seed/load_seed.py

#     bash:
export EMBED_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
export EMBED_API_KEY=sk-你的key
python seed/load_seed.py
```

成功时输出类似：

```text
[embed] model=text-embedding-v3 dim=1024 props=28 plans=11
[embed] ok
[seekdb] props=28 revenge_plans=11
[selftest] query='黏糊糊、甜得拉丝的东西'
  - 蜂蜜  score=...
```

最后一行是自检：用「黏糊糊、甜得拉丝的东西」做纯向量检索，命中「蜂蜜」说明向量链路通。

## 5. 启动 PowerContext

```bash
uv tool install --force "powercontext[cli,server]==1.5.0"

mkdir -p powercontext-config && cd powercontext-config
powercontext config init --output .env     # 交互式：存储选 SQLite，能力选 Basic memory
powercontext server run --env-file .env    # 保持这个终端
```

验证：

```bash
curl --fail http://127.0.0.1:8000/health/live
```

说明：

- 本作品只用 **显式记忆写入/召回**（`/v1/memory/remember`、`/v1/context/prepare`），Basic memory 足够，服务端不需要额外模型 Key。
- PowerContext 的存储选 SQLite 即可；**不要**把它和 seekdb 混为一谈：seekdb 存游戏世界与账本，PowerContext 存叙事记忆，分工见[设计文档](01-作品设计.md#7-技术分工与必要性论证评分重点)。
- Windows 支持为 experimental；若 `powercontext server run` 异常，改用 WSL2 或 Linux 跑 PowerContext，bridge 里把 `POWERCONTEXT_URL` 指向它即可。

## 7. 部署 Dify

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d
# 浏览器打开 http://localhost，首次进入设置管理员账号
```

安装模型供应商：右上角头像 → **设置 → 模型供应商 → DeepSeek → 安装 → 填 API Key**（或选任意已装好的 Chat 模型）。

> 如果 Dify 在 Linux 宿主机上，容器默认访问不到宿主机的 `host.docker.internal`。在 `dify/docker/docker-compose.yaml` 的 `api` 与 `worker` 服务下加：
>
> ```yaml
>     extra_hosts:
>       - "host.docker.internal:host-gateway"
> ```
>
> 然后 `docker compose up -d`。

### 7.1 必做：放行内网地址（Dify 的 SSRF 防护）

Dify 的 HTTP Request 节点默认拒绝访问私有/回环地址。不加放行，调用 bridge 会直接报：

```text
Access to 'http://host.docker.internal:8099/...' was blocked by SSRF protection.
The URL may point to a private or local network address.
```

在 `dify/docker/.env` 中按官方变量放行**只包含 bridge 的最小网段**：

```dotenv
# 只放行 bridge 所在网段与域名，不要写 0.0.0.0/0
SSRF_PROXY_ALLOW_PRIVATE_IPS=172.17.0.0/16
SSRF_PROXY_ALLOW_PRIVATE_DOMAINS=host.docker.internal
```

然后重建相关容器：

```bash
cd dify/docker
docker compose up -d ssrf_proxy api worker
```

CIDR 按你机器实际网段调整：`docker network inspect bridge` 看 ` Gateway`，或 `docker exec -it docker-api-1 getent hosts host.docker.internal` 看解析到的地址。这一段是**基础验收能否跑通的关键**，请务必先自测：

```bash
docker exec -it docker-api-1 curl -s http://host.docker.internal:8099/healthz
```


## 8. 导入 DSL 并绑定

1. Dify → **工作室 → 创建应用 → 导入 DSL 文件**，选择 `dify/grudge-tavern.dsl.yml`。
2. 打开应用 → 点「③ 老陈开口（LLM）」节点 → 模型选择 `deepseek-chat`（或你装好的模型）。若供应商不同，provider 会显示为未安装，换成本地已有的 Chat 模型即可。
3. 检查三个 HTTP 节点的 URL：
   - `http://host.docker.internal:8099/v1/props/search`
   - `http://host.docker.internal:8099/v1/memory/prepare`
   - `http://host.docker.internal:8099/v1/memory/commit`
   
   若 bridge 不在宿主机 8099，改成实际地址（三者要一起改）。
4. 右上角「发布 → 运行」，发送：

   > 我把吧台上的盐罐换成了糖罐

5. 期望看到：老陈的台词 + 状态面板（记仇值从 0 涨到 15~25，账本写着「把盐罐换成了糖罐」）。

### 8.1 如果 DSL 导入失败（版本不兼容的兜底）

新建一个 **Chatflow（对话流）**，按下面 9 个节点重搭即可，逻辑与 DSL 完全一致：

| 顺序 | 节点类型 | 关键配置 |
| --- | --- | --- |
| 1 | 开始 | 变量留空，使用 `sys.query` / `sys.user_id` |
| 2 | HTTP 请求 | POST `.../v1/props/search`，JSON body：`user_id={{#sys.user_id#}}`、`query={{#sys.query#}}`、`limit=6` |
| 3 | HTTP 请求 | POST `.../v1/memory/prepare`，JSON body：`user_id`、`query`、`max_bytes=2000` |
| 4 | LLM | 模型任选；system 写角色规则；user 注入 `sys.query` + `http_props.body` + `http_memory.body`；要求只输出 JSON |
| 5 | 代码 | 输入：LLM text、`http_memory.body`、`http_props.body`；输出：`reply/ledger/prop_used/grudge/mood/ending/final_text/ending_text` |
| 6 | HTTP 请求 | POST `.../v1/memory/commit`，body 用第 5 步的 8 个输出 |
| 7 | 条件分支 | `code.ending` 等于 `yes` → 结局分支，否则日常分支 |
| 8 | 直接回复 | 日常：`{{#code.final_text#}}` |
| 9 | 直接回复 | 结局：`{{#code.ending_text#}}` |

节点里的提示词与代码可以整段从 `dify/grudge-tavern.dsl.yml` 复制（YAML 里的 `prompt_template` 与 `code` 字段就是原文）。


## 9. 网络、资源与降级

### 9.1 网络

- Dify 容器 → bridge：`host.docker.internal:8099`（Docker Desktop 开箱可用；Linux 见上面的 `extra_hosts`，并且必须按 7.1 放行 SSRF）。
- bridge → seekdb：默认 `127.0.0.1:2881`；容器内是 `seekdb:2881`。
- bridge → PowerContext：默认 `127.0.0.1:8000`；容器内是 `host.docker.internal:8000`。
- bridge → Embedding API：需要出网（HTTPS）。
- Dify 的 SSRF 代理默认读超时 5 秒；bridge 单次请求通常在 1 秒内。若 Embedding 服务较慢导致超时，可在 `.env` 调大 `SSRF_DEFAULT_READ_TIME_OUT`。

### 9.2 没有 Embedding Key 的降级模式

```bash
python seed/load_seed.py --skip-embed
# bridge 的 .env 里不填 EMBED_BASE_URL
```

此时 `props/search` 走 `fulltext + 结构化`，仍能命中「盐罐」「糖罐」这类精确词，但「黏糊糊的东西」这种语义召回会变弱。状态面板会显示 `mode=fulltext`，可作为「降级但仍可玩」的说明。

### 9.3 资源

| 服务 | 建议 |
| --- | --- |
| seekdb | ≥ 2 vCPU / 2 GB（`MEMORY_LIMIT=2G`） |
| Dify | ≥ 4 GB 可用内存，首次拉镜像约 5–8 GB |
| PowerContext | 轻量，SQLite 模式 < 500 MB |
| bridge | < 200 MB |

## 10. 重置、清理与复现

```bash
# 重置某个玩家（清账本、新建 PowerContext scope）
curl -X POST http://127.0.0.1:8099/v1/reset \
  -H "Content-Type: application/json" \
  -d "{\"user_id\":\"demo-player\"}"

# 完全重来
docker rm -f tavern-seekdb && rm -rf seekdb-data
docker compose down          # 如果用了 deploy/docker-compose.yml
# Dify 应用可在「工作室」里删除后重新导入 DSL
```

> 复现验证时，**先 reset 再按样例顺序输入**，否则记仇值会带着上一局的状态。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `mysql` 连接被拒 | seekdb 还在初始化 | 等 30–60 秒，`docker logs tavern-seekdb` 看到 ready 再试 |
| 建表报 `FULLTEXT ... PARSER` 错 | 镜像版本较老，不支持 IK | 把 `00_schema.sql` 里的 `WITH PARSER ik PARSER_PROPERTIES = (ik_mode = "max_word")` 改成 `WITH PARSER ngram`，或升级镜像 |
| `DBMS_HYBRID_SEARCH` 不存在 | seekdb 版本过老 | 升级到最新 `oceanbase/seekdb` |
| `load_seed.py` 报维度不一致 | Embedding 模型维度 ≠ 1024 | 统一 `EMBED_DIM` 与 `VECTOR(1024)`，或改表定义后重建 |
| Dify HTTP 节点超时/500 | 容器访问不到 bridge | `docker exec -it docker-api-1 curl http://host.docker.internal:8099/healthz` 自测；Linux 加 `extra_hosts` |
| HTTP 节点报 `blocked by SSRF protection` | Dify 默认拒绝内网地址 | 按 7.1 节在 `dify/docker/.env` 配 `SSRF_PROXY_ALLOW_PRIVATE_IPS` / `SSRF_PROXY_ALLOW_PRIVATE_DOMAINS`，然后 `docker compose up -d ssrf_proxy api worker` |
| 记忆一直为空 | PowerContext 没起 / scope 没建 | 看 `bridge` 日志与 `players.scope_id`；`curl :8000/health/live` |
| 老陈台词不是 JSON | 模型没遵守格式 | 降低 LLM 温度到 0.6，或换更强的模型；Code 节点有兜底，不会崩，但数值会退化 |
| 面板里记仇值不涨 | LLM 没给 `grudge_delta` | 检查 prompt 是否被改；看 Dify 节点执行详情里的 LLM 原始输出 |

## 12. 已知限制

1. **单用户演示**：bridge 没有鉴权，只适合本机/内网。
2. **PowerContext Windows 支持为 experimental**：建议 WSL2/Linux。
3. **DSL 版本绑定**：`0.7.0` 对应 Dify 1.16+；更低版本导入后可能需要在画布上重连节点。
4. **JSON 依赖模型自觉**：极端情况下 LLM 输出不合格式，Code 节点会兜底成「纯文本台词 + 0 增量」，游戏不崩但数值不准。
5. **中文全文检索依赖 IK 分词**：若镜像不支持，关键词召回会退化（向量仍工作）。
6. **没有 Rerank**：道具只有 28 件，混合检索足够；素材规模变大时应加 Rerank。
7. **成本**：每回合 1 次 LLM + 1 次 Embedding（检索时），演示成本可忽略。
8. **VECTOR 列读回受驱动限制**：本机 pymysql 读取该列会报 `5083 Invalid data type`，因此**检索不要把向量读回应用层**（本作品的做法是把查询向量拼进 `DBMS_HYBRID_SEARCH` 参数，不读回）。

### 13.3 实测踩到的坑（已写回本文档与 DSL）

1. **seekdb：带 `PRIMARY KEY` 的表不能做混合检索**（`1235 table with user provided primary key not supported`）。
   → `props` / `revenge_plans` 改为不声明主键，用 `UNIQUE KEY (id, name)`。

2. **Dify 1.19 的 HTTP 节点 JSON body 只接受单条 item**（`json body type should have exactly one item`）。
   → body 改为 `data: [{key: "", type: "text", value: "<整段 JSON>"}]`。

3. **`retry_config: null` 会被 Dify 1.19 拒绝**（`Input should be a valid dictionary`）。
   → DSL 里已移除该字段。

4. **模型名变了**：插件 0.0.26 只暴露 `deepseek-flash` / `deepseek-v4-flash` / `deepseek-v4-pro`，没有 `deepseek-chat`。
   → DSL 默认模型改为 `deepseek-flash`；若你的插件版本仍提供 `deepseek-chat`，在 LLM 节点里改回即可。

5. **PowerContext 1.5.0 的 `powercontext server run` 在本环境不可用**（`jieba` 无 wheel、`[server]` 依赖装不全、CLI 无 `server` 子命令）。
   → 兜底脚本 `scripts/pc_server.py`：用 `open_builtin_runtime(BuiltinConfig(database=sqlite))` + `create_app()` 组装同一个 Server，接口一致；`jieba` 从 HTTP 镜像拿 sdist 解压进 site-packages。正式环境仍建议用官方 `powercontext server run`。

6. **Windows 下 pgvector 的单文件挂载会失败**（`/docker-entrypoint.sh` mount 报 not a directory）。
   → `dify-stack/docker-compose.override.yaml` 去掉该挂载，改用镜像自带入口。

7. **Dify 控制台登录密码是 Base64 传输**（`FieldEncryption` 只做 base64），且非 GET 请求必须带 `X-CSRF-Token`。
